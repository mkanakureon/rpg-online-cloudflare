# ADR 0003: 配布の形・ライセンス・サポートの範囲

- **日付:** 2026-11-01
- **状態:** 採用
- **元の設計:** `docs/guides/working/distribution-design.md`（配布／OSS 公開の設計書。§2・§7・§12 の 9・10）
- **置き換えるもの:** ADR 0002 の「名前の変更とライセンス（MIT を推す）は、公開する時に決める」のうち、ライセンスを決める部分。リポジトリの名前は、この ADR でも案までで変えない

## 背景

Phase 4（配布／OSS 公開）で、ゲーム作者がこのバックエンドを自分の Cloudflare にデプロイして使える形にする。そのために、何をどの形で配るか・どのライセンスで出すか・作者からの問い合わせをどこまで受けるかを先に決めておく必要がある。細部と束の順は `distribution-design.md` にあり、この ADR は後から覆りにくい決定と、その理由だけを残す。

## 決定

- **配布の形はゲーム別独立デプロイ。** 作者ごと（ゲームごと）に独立の Worker と D1 を、作者が自分の Cloudflare のアカウントにデプロイする。このリポジトリのフォークか写しを取って使う。1 つの Worker で多くの作者を受ける共有ホスティングは範囲の外（ADR 0002 の「ゲームごとに別々にデプロイする」を配布の形として確かめる）。
- **ライセンスは MIT。** リポジトリ直下の `LICENSE` に全文を置き、著作者の行は `Copyright (c) 2026 mkanakureon`。配るもの（Worker のコードと `clients/` のクライアントの層）に第三者の包みを入れない。`package.json` は `dependencies` を持たず、`devDependencies` は開発の道具で配らない。
- **サポートの範囲**（`README.md` の「サポートの範囲」の節に書く）:
  - 無保証（MIT のとおり）。
  - Issue で受けるのは、最新の版で再現できる不具合だけ。
  - 利用者の Cloudflare の設定・料金・データの復元はサポートしない。
  - 応答の期限を約束しない。対応する版は最新の 1 つだけ。
- **リポジトリの名前は変えない（案だけ）。** いまの `rpg-online-cloudflare` は ADR 0002 の目的（エンジンに依存しないゲームバックエンド）より狭い。案は `game-backend-cloudflare`（推し。目的をそのまま表す）・`cf-game-backend`・`open-game-backend`。名前を変えるのは GitHub の設定で、外への操作なのでユーザーがする。変えた後のリポジトリの中の文字列（`package.json` と `wrangler.jsonc` の `name`・スキーマの `title`・Unity の包みの名前）は、別の束で直す。
- **Fab に出すときの境目。** RPG 制作ツールのアドオンとして Fab に出すなら、出すのは Unreal の層（`clients/unreal/` のプラグインとイベントコマンドの橋渡し）だけにする。サーバーは Fab の製品に含めず、MIT の OSS としてこのリポジトリから作者が取ってデプロイする。Fab の規約（OSS のコードを含む製品・外のサービスに依存する製品・サポートと返金・生成 AI で作ったコードの申告）は人が確かめる（`distribution-design.md` §7.4）。Unity の Asset Store は範囲の外。
- 守り（書き込みの API を `APP_ENV=local` のときだけ通す門）を外すかどうか・いつ外すかは、この ADR では決めない（`distribution-design.md` §3。ユーザーが決める）。

## 理由

- ゲーム別独立デプロイなら、データの隔離・課金・サポートを作者ごとの Cloudflare のアカウントに閉じ込められ、マルチテナントの運用を背負わずに済む。いまの作り（`tenant_id` を持たず `game_id` を持つ）をそのまま使える。
- MIT はゲームへの組み込みで扱いが一番軽く、作者がクライアントの層を自分のゲームに写して配っても条件は著作権の表示だけで済む。配るものに第三者の包みが入らないので、依存の包み（開発の道具の下にある LGPL・MPL を含む）のライセンスと矛盾しない。Apache-2.0 の特許の条項は、この規模では利点より説明の手間が大きい。
- サポートを「再現できる不具合だけ」に絞ると、作者ごとの Cloudflare の設定と料金という、持ち主が見られないものへの約束を避けられる。

## トレードオフ

- MIT は特許の許諾を明示しない。必要になったら Apache-2.0 への切り替えを別の ADR で決める（それまでの版は MIT のまま残る）。
- 作者ごとにデプロイするので、更新は作者がフォークに取り込んで自分でデプロイし直す。版の移行の説明が要る（`distribution-design.md` §8.3）。
- サポートを絞るので、Cloudflare に慣れていない作者には敷居が残る。デプロイと運用の説明書（`docs/guides/manuals/`。束 P2・P3）で埋める。
