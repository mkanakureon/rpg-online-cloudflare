# ADR 0001: Macで先にCloudflareサーバーを作り、CLIモックで検証する

- **日付:** 2026-10-22
- **状態:** 採用

## 背景

開発用PCが3台ある。Windowsの1台はUE製RPG制作ツール、もう1台はUnity開発を担当する。余っているMacはNode.js/TypeScript開発に活用できる。オンライン機能を作るために、UEクライアントを頻繁にビルドしたり起動したりする必要はない。

## 決定

- TypeScript/Cloudflare Workers/D1をサーバーの主要技術にする。
- **Macでサーバー開発を先行し、CLIモックを唯一の初期クライアントとする。**
- CLIモックはUEから送る予定のHTTP/JSONを再現し、成功・失敗・リトライをテストする。
- UE本体の実装を待たずにAPI契約、マイグレーション、テストを進める。
- 将来のUE統合ではC++のアダプターが同じAPIを呼び出す。

## 理由

- PCの作業競合が減る。
- Worker/D1のローカル試験はMacBook Air M1のような軽量環境でも比較的取り組みやすい。
- サーバーをUEから独立させることで検証速度と再利用性を高められる。
- Unity側も巻き込まずに開発を分離できる。

## トレードオフ

- CLIモックだけでは実際のUEの通信タイムアウトやゲーム画面のUXを再現できない。
- クライアント側の認証情報・非同期UI・保存・回線断は、UE統合時に別途テストする必要がある。
- APIをドキュメント化しないとCLIとUEの実装差が生まれるため、仕様とテストを共通化する。
