# 開発計画: Mac先行・CLIモック運用

## なぜ先にサーバーを作るか

- 3台のPCを作業別に分担し、Macの余剰リソースを活用する。
- UEクライアントの変更や起動を伴わずにサーバーの機能・データモデルを検証する。
- APIを先行確定させておけば、Windows側でUEアダプターを実装するだけで統合できる。
- Unity機側の開発とも依存関係を作らない。

## 優先的にテストする失敗ケース

1. ネットワーク切断／タイムアウト／サーバーエラー
2. 存在しないゲーム・ランキングボード
3. スコアがマイナス、整数でない、巨大すぎる
4. 他ゲームのレコード取得を狙うリクエスト
5. スコアを高速連投する／同じイベントを二重送信する
6. サーバーとローカル時刻が異なる
7. D1スキーマ変更後の旧CLIとの互換性
8. 認証切れ／不正トークン（認証実装後）

## 担当PC

- **Mac:** サーバーAPI・CLI・Cloudflareローカル検証。
- **UE専用PC:** 本体ゲーム／エディタの開発継続。サーバーが安定するまでは接続しない。
- **Unity専用PC:** Unity作業継続。サーバー開発とは独立。
