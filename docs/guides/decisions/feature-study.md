# UE製RPG制作ツール向けオンラインサーバー機能 検討書

**作成日:** 2026-10-22  
**状態:** 企画・技術選定（「1. 目的」の RPG 専用という位置づけは [ADR 0002](../../adr/0002-engine-agnostic-game-backend.md) で置き換えた）  
**想定製品:** Unreal Engine製RPGツクール型ツール向けのオプション／付属サーバー

## 1. 目的

- 1人用RPGに、少量のサーバーイベントでオンライン要素を追加できるようにする。
- ゲーム作者がTypeScript・サーバー運用を深く知らなくても、制作ツールのイベントエディタから利用できることを目指す。
- Cloudflare Workers上に、作者ごとに独立してデプロイ可能なサーバーのテンプレート／ソースを提供する。
- 既存のUE製RPG制作ツール（C++＋JSON、イベント実行機構）に将来接続する。初期開発はMacのCLIモックで完結する。

## 2. 方針と非目標

**方針**

1. `REST/HTTPS + JSON` を最初の通信方式とし、リアルタイム性が必要になった時にWebSocketを検討する。
2. 同じWorker APIをCLIモックと将来のUEクライアントが利用する。
3. 小さな作品でも役立つ「非同期オンライン要素」を重視する。
4. ゲーム作者自身のCloudflareアカウントにデプロイする自己管理モデルを基本とする。
5. 先に契約とローカル検証を作り、UE専用部分は後回しにする。

**現段階で実装しないもの**

- MMORPG、常時接続の大人数同期、アクションゲームの物理同期
- 決済・実通貨の取引所、マイクロトランザクション
- 不正対策なしの本番ランキング、匿名投稿の一般公開
- サーバーがゲーム作者の代理で全ユーザーを運営する共有SaaS

### 初期リリース想定

**P0:** 認証設計、ヘルスチェック、お知らせ、ランキングのAPIとCLIテスト。  
**P1:** 掲示板、期間限定イベント、ゴースト冒険者（公開運用に必要な対策を先に導入）。  
**P2以降:** ワールドボス、PvP、ギルド、取引所。

## 4. 体験として差別化しやすい機能

### 酒場掲示板

- 場所IDとゲームIDを指定してメッセージ取得・投稿。
- 町の掲示板、ヒント、プレイヤーの伝言に利用できる。
- 禁止語・連投制限・通報・削除・有効期限が必須。

### ゴースト冒険者

- プレイヤーの冒険者を公開用JSONで登録。別のプレイヤーが取得してNPCとして登場させる。
- 共有対象は公開プロフィール、クラス、装備テンプレートIDなどに制限し、任意アセットや実行可能コードを受け取らない。

### 日替わりクエストとライブイベント

- サーバーでイベントID、開始／終了時刻、達成条件、報酬コードを管理。
- ゲーム側は事前実装したクエストやアセットをイベントIDで有効化。新規アセット配信は別仕様とする。
- ローカル時計の変更で報酬を再獲得できないよう、サーバーが判定する。

### 全員共通ワールドボス

- 各プレイヤーが非同期で攻撃結果を送信し、共通HPを更新。
- 攻撃の真偽と残HPの競合解決が必要。Durable ObjectsやD1のトランザクション設計を検討する。
- 大規模リアルタイム同期よりも軽量なオンライン体験。

## 5. 商品の方向性

1. **RPG制作ツール本体**：オンライン機能呼出し用イベントコマンドとHTTPクライアント。
2. **Cloudflare Server Add-on**：TypeScriptソース、D1マイグレーション、Wrangler設定、CLI試験ツール、管理UI（後日）。
3. **サンプルゲーム**：ランキング・酒場掲示板・日替わりクエストの実例。

販売価格、購入者数、Fabでの登録条件、同梱ライセンスは未検証。収益予測を本資料の事実として扱わない。

## 6. 成功条件

- MacのみでローカルAPIの変更・動作確認ができる。
- CLI試験ツールで正常系・異常系・認証失敗を再現できる。
- RPGの新しいイベントコマンドからAPIを呼ぶ仕様が明確である。
- アカウント／ゲーム／プレイヤー／データの所有範囲が定義済みである。
- ステージング環境で運用上の最低限の監視・バックアップ・利用上限を検証できる。

## 7. 未確定事項

- 投稿内容のモデレーション方針。
- セーブ競合解決、暗号化、削除・バックアップ方針。
- Fabでの配布単位、サポート責任範囲、価格。
