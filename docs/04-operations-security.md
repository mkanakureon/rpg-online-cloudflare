# 運用とセキュリティの検討事項

> **現状:** 付属コードはローカルPoCであり、本番公開を想定しない。無認証のスコア投稿はローカル実行時に付与する`APP_ENV=local`でのみ許可し、本番用デプロイ手順は未提供。

## 公開前の必須要件

1. **本人確認:** Steam向けならSteam認証等のサーバー側検証。Steam以外には適切な代替方式を用意。
2. **認可:** ゲームID／プレイヤーIDの単純申告だけでは他者データの読書き許可に使わない。
3. **不正対策:** ランキング値の自己申告は改ざん可能。競争要素が強い機能はサーバー側検証、リプレイ照合等を検討。
4. **レート制限:** IP・アカウント・ゲーム・エンドポイント単位の制限。掲示板は荒らし対策とモデレーションが必要。
5. **操作の原子性:** 報酬二重取り、在庫競合、アイテム重複を防ぐ。KVは整合性の厳しい更新に不向き。
6. **プライバシー:** 個人情報は最小化し、ログの保持期間・削除手順を定義する。
7. **秘密情報:** `.dev.vars`、APIトークン、管理用キーなどをGitにコミットしない。秘密情報はWranglerのSecrets等で管理。
8. **データ保持:** D1とR2のバックアップ、復元演習、セーブ競合と容量制限を決める。
9. **配布責任:** ゲーム作者がCloudflare料金と運用責任を持つモデルでは、設定ガイドとコストアラートを必須とする。
10. **環境分離:** local／staging／productionのDB・秘密情報を分離する。

## ログ・監視

- リクエストID、エンドポイント、遅延、ステータス、エラーコードを構造化ログに記録。
- トークンやセーブの本文など機密データは記録しない。
- DB使用量、呼出回数、予算上限を監視。
- メンテナンスモードと緊急停止の手順を事前に用意する。
